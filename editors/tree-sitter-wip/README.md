# tree-sitter-wip

A [Tree-sitter](https://tree-sitter.github.io) grammar for Wip, which the
editor support in `editors/zed` and `editors/nvim` is built on. It is for
highlighting, folding and indenting, and does not replace the compiler's
parser. It accepts every program the compiler does, and may accept some it
refuses.

- `grammar.js` is the grammar. `docs/grammar.md` is what it follows.
- `src/scanner.c` finds the line break that ends a statement.
  It gives one only where the parser could end something there, so a line
  break inside brackets or after an operator stays space, and never before
  `else`.
- `src/parser.c` and the rest of `src/` are generated by `tree-sitter
  generate`. They are committed because editors build the grammar from
  them.
- `queries/` holds highlights, folds, indents and locals. The capture names
  follow Neovim's conventions, which Zed reads too.
- `test/corpus/` holds the grammar's tests.

## A reading the grammar has to choose

One place is ambiguous for a left-to-right parser, and the grammar lets it
fork and prefers the ordinary reading (`prec.dynamic(-1)` on the other):
`a < b` is a comparison, unless it can only be type arguments, as
`Vec<i64>()` can. A struct is built with a call, so a `{`
after `while i < n` is always the loop's body.

## Checking it

```sh
scripts/tree-sitter.sh
```

This regenerates the parser, runs the tests, compiles the queries, and
parses every `.wip` file in the repository, which must give no error. Run
it after any change to the syntax, and commit the regenerated `src/` with
it. `scripts/tree-sitter.sh --check` changes nothing, and fails where
`src/` is not what `grammar.js` makes or where a file does not parse; the
gate runs it where `tree-sitter` is installed.
